# 네이버 블로그 자동 작성 툴 (Naver Blog Auto Writer)

> 사진 몇 장 넣고 메모 한 줄 쓰면,
> 네이버 상위노출 공식이 적용된 블로그 글이 완성되고 임시저장까지 됩니다.

이 폴더는 아래 **[제작 프롬프트]** 로 만들어지는 툴의 **완성 예시(레퍼런스 구현)** 입니다.
수강생은 두 가지 방법 중 하나로 쓸 수 있어요:

- **A. 직접 만들기(추천)**: 아래 가이드대로 새 폴더에서 프롬프트를 붙여넣어 처음부터 만든다. AI가 인터뷰하며 내 업종에 맞춰 최적화해준다.
- **B. 완성본으로 시작하기**: 이 폴더를 통째로 복사 → `npm install` → `npx playwright install chromium` → Claude Code 실행 → 첫 대화에서 "내 블로그 정보 인터뷰부터 해줘"라고 입력. (CLAUDE.md의 대괄호가 채워지며 내 것이 됩니다)

---

ChatGPT한테 "블로그 글 써줘" 해본 분들은 알 거예요. 어색한 말투, 지어낸 정보, 광고 티 팍팍 나는 글. 결국 다 뜯어고치게 되죠.

이건 접근이 달라요. **Claude Code 안에 "15년차 파워블로거의 작업 방식" 자체를 통째로 설치하는 겁니다.** 실제 발전기 업체 블로그와 맛집 블로그에서 실전 검증하며 다듬은 프롬프트고, 업종만 바꾸면 어디든 적용됩니다.

## [이 툴이 하는 일]

- 검색자 1명을 구체적으로 정하고(페르소나), 그 사람 마음에 꽂히는 첫 문단부터 씁니다
    - 폴더에 넣은 **사진을 AI가 직접 보고** 분석해요 (간판·메뉴판·작업 장면을 읽어냄)
- 키워드 배치, 가독성, 저품질 회피까지 네이버 SEO 공식이 자동 적용돼요
- 사진에 타인 얼굴·차량 번호판 같은 개인정보가 보이면 알려주고, 승인하면 모자이크 처리까지 해서 올려요
- 완성되면 **네이버 블로그에 임시저장까지** 자동으로 — 글·사진은 물론 **태그, 지도(플레이스), 동영상, 소제목 서식까지** 자동 입력돼요. 저장된 글을 초안과 글자 단위로 대조하는 검증까지 마치면, 발행 버튼만 내가 누르면 끝
- API 요금 없음 — Claude 구독 토큰으로만 돌아갑니다

## [시작 전 체크]

- 준비물: **Node.js**(무료), **Claude Code**(프로그램 자체는 무료), **Claude 유료 구독**, **네이버 계정**.
- 💰 **비용 구조, 정확히 알고 시작하세요**: Claude Code는 유료 구독(Pro 이상)이 있어야 쓸 수 있어요. 대신 별도 API 요금은 전혀 안 나갑니다 — 구독에 포함된 사용량으로 돌아가게 설계된 툴이에요. 그리고 이 툴은 "한 번 만들면 끝"이 아니라 **글을 쓸 때마다 AI가 일하는 구조**라, 계속 쓰려면 구독을 유지해야 합니다. 해지하면 만들어둔 파일은 남지만 글 자동 작성은 멈춰요.
- 상위 모델(Opus 등)은 글 품질이 좋은 대신 구독 사용량을 빨리 소모해요. 글쓰기만 상위 모델로 돌리는 게 가성비 요령.
- ⚠️ 임시저장 자동화는 브라우저 자동화 방식이라 네이버 약관상 회색지대예요. 본인 계정, 하루 1~2건 수준으로만.
- 💡 참고: 클로드 웹 "프로젝트"로는 글 생성까지만 가능해요. 임시저장 자동화까지 쓰려면 컴퓨터에서 코드를 실행할 수 있는 Claude Code가 필요합니다.
- 소요 시간: 최초 설치+세팅 1시간 이내, 이후 글 1편에 몇 분

## [STEP 0. 설치 — 처음 한 번만]

이미 Node.js와 Claude Code가 설치돼 있다면 건너뛰세요. (혹은, 클로드코드만 열고 Node.js 설치해달라고 하시면 됩니다)

1. **Node.js 설치**: nodejs.org에서 LTS 버전 다운로드 → 계속 "다음"으로 설치.
2. **터미널 열기**: 바탕화면이나 폴더의 빈 공간에서 마우스 우클릭 → **"터미널에서 열기"**. (이게 안 보이면 시작 메뉴에서 "PowerShell" 검색)
3. **설치 확인**: 터미널에 `node -v` 입력 → 버전 숫자가 나오면 성공.
4. **Claude Code 설치**: 터미널에 아래 입력 → 끝나면 터미널을 **닫았다가 다시** 여세요.

```
npm install -g @anthropic-ai/claude-code
```

**5. 로그인** — 새 터미널에서 `claude` 입력 → 첫 실행 시 테마 선택 후 로그인 화면이 나오면 **유료 구독 중인 Claude 계정**으로 로그인하세요. (이걸로 구독 사용량이 연결돼서 API 요금이 안 나가는 겁니다)

## [이 가이드의 단 하나의 규칙]

아래 STEP을 외울 필요 없습니다. **뭐가 되든 막히면 Claude Code 채팅에 그냥 물어보세요.** 설치가 안 돼도, 오류가 떠도, 다음에 뭐 해야 할지 모르겠어도 — "지금 이런 상황인데 어떻게 해?"라고 치면 됩니다. 이 툴을 만드는 것도, 고치는 것도, 사용법을 알려주는 것도 전부 같은 AI가 합니다. 이 가이드는 지도일 뿐, 운전은 AI가 해요. AI가 뭔가를 추천하면 그대로 따라가는 게 기본값으로 맞습니다.

## [STEP 2. 대괄호 4칸 채우기]

붙여넣기 전에 `[대괄호]` 부분만 내 상황으로 바꾸세요 — 주제, 목표, 지역, 화자 톤. (화자 톤은 비워두면 AI가 인터뷰로 정해줍니다)

새 폴더를 만들고, 그 폴더에서 터미널을 열어 `claude`를 실행하세요.

그다음 `/model`을 입력해 모델을 확인합니다. 추천은 이래요:

- **처음 툴을 만들 때와 평소 글쓸 때**: 선택 가능한 가장 상위 모델 (Opus 등). 글의 미묘한 말맛과 후킹 품질이 여기서 갈립니다.
- **트렌드 분석이나 오류 수정 같은 기계적 작업**: Sonnet으로도 충분 — 구독 사용량을 아끼는 요령입니다.

## [STEP 4. 계획 모드로 프롬프트 붙여넣기]

붙여넣기 전에 **Shift+Tab을 두 번** 눌러 `plan mode`로 바꾸세요. 이 모드에서 프롬프트를 붙여넣으면 AI가 바로 만들기 시작하는 게 아니라, 먼저 **질문**하고(말투, 업체 정보, 목표 키워드 등) 전체 **제작 계획을 보여줍니다.**

계획을 읽어보고 이상한 부분이 없으면 승인하세요. (계획 단계에서 방향을 잡고 시작하면 중간에 엉뚱한 걸 만들어서 다시 하는 일이 없어져요.)

## [STEP 5. 자동 모드로 전환 후 따라가기]

계획 승인 후 **Shift+Tab 한 번**으로 auto-accept(자동 승인) 모드로 바꾸세요. 그럼 파일 생성·명령 실행마다 묻지 않고 알아서 끝까지 만듭니다.

이후는 **AI가 안내하는 순서를 그대로 따라하기만 하면 돼요**: `npm install` → 네이버 로그인 1회(세션 저장, 비밀번호는 저장 안 됨) → 첫 테스트 글 검수. 중간에 막히면 에러 메시지를 그대로 AI한테 보여주면 알아서 고칩니다.

💡 단, 자동 모드여도 글 초안의 **임시저장 전 검수 확인**은 항상 채팅으로 물어봅니다 — 이건 안전장치라 꺼지지 않아요.

## [자주 막히는 지점 — 실제로 다 겪어본 것들]

1. **"이 시스템에서 스크립트를 실행할 수 없으므로..." 오류** → PowerShell 보안 정책 문제예요. 터미널에 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` 입력 후 `Y`. 한 번만 하면 됩니다.
2. **"claude 용어가 인식되지 않습니다"** → 설치 직후라 그래요. 터미널을 닫았다가 다시 열면 인식됩니다.
3. **"'&&' 토큰은 올바른 문 구분 기호가 아닙니다"** → 구형 PowerShell은 명령 이어붙이기(&&)가 안 돼요. 명령을 한 줄씩 따로 실행하세요.
4. **네이버 로그인이 풀렸을 때** → 채팅에 `/setup-login` 입력하면 로그인 창이 다시 떠요. 패스키 로그인도 됩니다.
5. **그 외 모든 오류** → 오류 메시지를 그대로 복사해서 Claude Code 채팅에 붙여넣으세요. 이게 이 방식의 진짜 장점인데, 도구를 만든 AI가 옆에 있으니 수리도 알아서 해줍니다.

## [자주 묻는 질문]

1. **"사진만 넣으면 되나요?"** → 거의요. 사진에서 읽을 수 있는 건(간판, 메뉴판, 가격) AI가 알아서 뽑고, 사진에 없는 정보(위치, 협찬 여부, 내 감상)만 한 줄 메모로 주면 됩니다. 이 한 줄을 생략하면 AI가 지어내는 대신 되물어보게 설계돼 있어요.
2. **"잘 쓴 블로그 글을 따라 하게 할 수 있나요?"** → 네, 이게 핵심 기능이에요. 벤치마킹하고 싶은 글을 `/learn-style`에 붙여넣으면 말투·구성·심리 전략을 학습하고, `/analyze-trends`에 주면 글자 수·사진 수·제목 구조 같은 세팅값을 뽑아 저장합니다. 문장을 베끼는 게 아니라 구조만 추출해서 유사문서 위험도 없어요.
3. **"알아서 발행까지 해주나요?"** → 아니요, 일부러 막아놨어요. 임시저장까지만 하고 발행은 항상 사람이 확인 후 직접. 거기에 저장된 글의 전체 텍스트를 초안과 글자 단위로 대조하는 검증까지 거칩니다.
4. **"쓸수록 똑똑해지나요?"** → 네. 학습한 스타일, 트렌드 세팅, 심지어 버그 해결 기록까지 전부 파일로 남아서 다음 세션에 승계돼요. 쓰면 쓸수록 내 블로그에 맞는 도구가 됩니다.
5. **"구독 해지하면 어떻게 돼요?"** → 만들어둔 툴과 학습 데이터는 내 컴퓨터에 파일로 그대로 남아요. 다만 글을 쓰는 건 AI니까, 구독을 다시 시작하면 이어서 바로 쓸 수 있습니다.

## [중요: 퀄리티는 당신이 주는 정보에 비례합니다]

이 프롬프트는 어떤 분야에도 쓸 수 있는 **범용 설계도**예요. 바꿔 말하면, 붙여넣기만 하면 나오는 건 "평균적인 툴"이고, 내 분야에 최적화된 툴은 제작 과정에서 내가 뭐를 주느냐가 결정합니다.

- **상세 정보를 아끼지 마세요**: AI가 질문할 때 성의껏 답할수록 글이 좋아집니다. 경력, 취급 품목, 단골 유형, 자주 받는 질문, 내 말버릇까지 — 구체적일수록 좋습니다.
- **레퍼런스를 꾸준히 학습시키세요**: 내 분야 상위노출 글을 보면 `/learn-style`과 `/analyze-trends`에 넣어주세요. 많이 학습할수록 내 분야 특유의 글 스타일에 가까워집니다. 만들자마자보다 한 달 쓴 후가 확연히 달라요.
- **첫 글부터 완벽할 순 없어요**: 초안을 보고 말투나 구성을 교정해주면 그 피드백이 파일로 쌓여서 다음 글에 반영됩니다. 도구를 "키우는" 감각으로 쓰세요.

⚠️ **결과는 사람마다 다를 수 있습니다.** 입력하는 정보의 양과 질, 학습시킨 레퍼런스, 사용하는 모델(Opus/Sonnet 등), 그리고 네이버 에디터·알고리즘 변화에 따라 결과물 품질과 동작 여부가 달라질 수 있어요. 상위노출과 수익을 보장하는 도구가 아니라, 꾸준한 발행을 돕는 도구입니다. 발행 전 최종 확인과 글에 대한 책임은 항상 작성자 본인에게 있어요.

## 만들 것

사용자가 사진 + 소재 정보 + 한줄 메모만 주면 → AI가 사진을 직접 보고 글을 써서 → 승인 후 네이버 임시저장까지 해주는 툴. 구성:

- CLAUDE.md (마스터 지침) + .claude/commands/ (/write, /learn-style, /analyze-trends, /setup-login) + .claude/settings.json (폴더 내 작업 자동승인)
- scripts/ — Playwright 자동화 (persistentContext로 세션 유지, 로그인은 사용자가 브라우저에서 직접 1회, 비밀번호 저장 금지): naver_login.js, naver_draft.js(글·사진·태그·지도·동영상·소제목 서식까지 자동 입력), mosaic.js(사진 모자이크), probe_selectors.js(셀렉터 진단용 DOM 덤프 — 읽기 전용)
- data/ — profile.md(사실 정보·CTA), blogger-profile.md(화자 캐릭터 — 매 글 일관성의 단일 기준), authority-lines.md(권위 문구 뱅크: 경력형/사례량형/솔직함형), photo-guide.md(업종별 필수 촬영 컷 가이드), sponsored-disclosure.md(협찬 표기 문구), trends.md, style-profile.md
- input/photos/, input/videos/, drafts/, package.json
- 초안 JSON 포맷: blocks(text/subtitle/image/quote/divider) + 최상위 필드 3개 — tags(발행 패널에 자동 입력되어 임시저장에 보존), place: {query, name}(지도가 글 맨 끝에 자동 삽입 — 지역 업종 글에서 필수. 검색 0건이면 로그에 수동 첨부 필요 표시), video: {path, title 40자 이내}(항상 첫 text 블록 직후 삽입, 업로드 수 분 소요)

## 절대 규칙

1. API 키 사용 금지 — 모든 AI 작업은 Claude Code 세션 안에서 (구독 토큰만 소모, claude -p 지원).
2. 발행 금지 — 임시저장까지만. 발행은 항상 사람이. 태그 입력을 위해 발행 패널을 열어야 하므로, 에디터 로드 직후 캡처 단계 클릭 리스너로 진짜 발행 버튼(button[data-testid="seOnePublishBtn"]) 클릭을 원천 차단하는 가드(installPublishGuard)를 스크립트에 반드시 넣어 이 규칙을 코드로도 보장한다. 어떤 경우에도 이 가드를 제거하지 않는다.
3. 사실 지어내기 금지 — profile.md와 사진에서 확인된 것만. 확인 안 된 정보는 사용자에게 묻는다.
3-1. 협찬 처리(공정위 표시광고법 — 생략 불가): /write마다 협찬·체험단 여부를 반드시 확인하고(메모에 없으면 질문), 협찬이면 data/sponsored-disclosure.md의 대가 유형별 표기 문구를 글 상단 첫 블록에 기본 포함한다(업체 지정 문구가 있으면 그것이 우선, quote가 아닌 일반 text 블록으로). "내돈내산"·"광고 아님" 같은 거짓 부인 표현은 위법이므로 협찬 글에 쓰지 않는다.
4. 소재는 고객 사례가 아니어도 된다(자사 장비·일상 소재 가능). 단 서사를 지어내지 말고 정직하게 자기 사례임을 밝히고 쓴다.
5. 학습 데이터 자동 수집 금지 — 사용자가 제공한 글로만 trends/style-profile 갱신.
6. 초안은 사용자 승인 후에만 임시저장.

## 글쓰기 공식 (실전 검증됨)

- 키워드: 메인 1개(지역명 포함, 제목 앞쪽·첫 문단·마지막 문단 배치, 본문 5~7회, 띄어쓰기까지 검색어와 동일하게 1회 이상) + 서브 2~3개(소제목 배치).
- 페르소나 설계 필수: 메인 키워드를 검색하는 1명을 구체적으로 정의(지역·나이·직책·상황·감정)하고 그 사람에게 말 걸듯 쓴다. 초안 검수 시 페르소나도 보고.
- 첫 문단 Yes-set: 첫 2~3문장에서 페르소나의 상황·감정을 적중시켜 "맞아, 내 얘기다"를 연속 유도 + 결론 예고. 예: "발전기 시동 버튼을 눌렀는데 아무 반응이 없으셨죠. 점검 날짜는 다가오는데 막막하실 겁니다. 결론부터 말씀드리면, 열에 아홉은 엔진 문제가 아닙니다."
- 둘째 문단 권위 한 줄: authority-lines.md에서 골라 변형해 툭 던지듯. 자랑·업체명·연락처 금지. 정보성 글엔 "솔직함형"(예: "업체 입장에선 이런 글 쓰면 안 되는데, 자꾸 당하는 분들이 계셔서 씁니다")이 가장 강력.
- 후킹 패턴은 매번 다르게 선택: 손실 회피형 / 현장 몰입형 / 반전형 / 공감형.
- 홍보 냄새 제거: 정보성 글 본문에 업체명 금지(CTA에서만 1회), 연락처는 글 전체 1회, 업체명 본문 3회 이내.
- 가독성(모바일 기준): 한 문장 = 한 줄, 한 블록 3~5줄, 리듬 파괴 장치(인용구/구분선/사진/소제목)를 300~400자마다, 핵심 문장은 인용구로 글당 2~4개. 텍스트만 500자 연속이면 실패작. 표는 "✔ 항목 — 내용" 체크리스트로 대체.
- 기본 세팅: 1,800~2,500자(정보성 3,000자까지), 사진 10~15장(장당 텍스트 2~4문단), 제목 25~32자. 유사문서·저품질 회피(도입 패턴 매번 변경, 사진 재사용 금지, 외부링크 1개, 광고 어휘·제목 특수문자 금지).
- 업종별 필수 정보 체크리스트: 제작 인터뷰에서 "검색자가 원하는 실측 정보 목록"을 업종에 맞게 정의해 CLAUDE.md에 박고, 초안 검수 때 항목별 대조한다. (예 — 맛집: 교통·주차·웨이팅·좌석 + 먹은 메뉴마다 메뉴명·가격·맛·팁 4종 세트 + 단점 1개 포함 총평. 확인 안 된 항목은 지어내지 말고 묻거나 뺀다.)
- 발행 체크리스트(임시저장 후 안내): 태그 5~10개·지도·동영상·소제목 서식은 스크립트가 자동 처리하므로, 실행 로그의 "자동 처리 결과" 블록을 확인해 실패 항목만 수동 안내한다. 넘어서 안내할 수동 항목: 타겟 활동 시간대 발행, 발행 후 24시간 수정 금지, 주 2~3회 주기(하루 2건 이상 금지), 협찬 표기 육안 확인.

## 사진·영상 처리

- 사진은 분석한 스토리 순서로 배치한다 (파일 순서 아님). 캅션(caption)에도 키워드 1~2회 자연 배치 — 전체 사진의 절반 정도만.
- **개인정보 모자이크 (scripts/mosaic.js, 필수)**: 사진에서 식별 가능한 타인 얼굴·차량 번호판·전화번호 등을 발견하면: ① 문제 영역 좌표(0~1 상대값, 상하좌우 15% 여유)를 담은 spec을 drafts/에 JSON으로 저장 ② mosaic.js 실행 — 처리본은 input/photos/_mosaic/에 생성되며 원본은 절대 덮어쓰지 않는다 ③ 처리본을 Read로 열어 실제로 가려졌는지 확인, 덜 가려졌으면 좌표를 키워 재실행 ④ 초안에는 처리본 경로 사용. 구현 함정 둘: 좌표 기준은 반드시 EXIF 회전 보정 후(보이는 화면 기준)로 잡을 것, sharp 사용 시 한 파이프라인에 resize는 1회만 적용되므로 축소→버퍼→확대(nearest)로 2단계 분리할 것. 검수 보고에 처리 내역(몇 장·몇 영역·사유)을 포함하고, 화자 본인 얼굴도 기본은 모자이크(공개를 명시한 경우만 예외).
- **동영상 자동 첨부**: input/videos/에 영상이 있으면 초안의 video 필드에 넣는다. 항상 첫 text 블록 직후에 삽입되며(D.I.A. 가산 요소), 영상 제목은 필수·40자 제한(video.title > 글 제목 > 기본값 순). 업로드에 수 분 걸릴 수 있다.

## 자가 검증 원칙 (이 툴의 품질 엔진 — 가장 중요)

모든 단계에서 "했다"가 아니라 "됐는지 확인했다"로 끝내라:
1. 이중 검증: 임시저장 후 (a) 스크린샷 + (b) 에디터 문서의 제목·본문 전체 텍스트를 덤프 파일로 추출해 초안과 전문 대조한다. 스크린샷은 화면 상단만 보이므로 텍스트 덤프가 본검증이다. 불일치하면 성공 보고 금지 — 원인을 찾아 수정한다.
2. 셀렉터가 실패하면 추측으로 고치지 말고, 실제 DOM을 검사하는 일회용 스크립트를 만들어 실측 후 수정한다.
3. 문제를 해결하면 원인과 해결책을 CLAUDE.md에 기록하고, 안정 버전 스크립트를 .working.js로 백업한다. 기억할 가치가 있는 건 전부 파일로 — 다음 세션은 대화를 기억하지 못한다.
4. 초안 검수 시 자가 질문: "모바일에서 인용구와 소제목만 훑어도 핵심이 전달되는가?"

## 실측 지식 (수십 시간 디버깅으로 확인 — 그대로 반영할 것)

- 본문 셀렉터는 .se-section-text p.se-text-paragraph 로 한정. 제목도 내부적으로 같은 문단 구조(p.se-text-paragraph)를 쓰기 때문에, 범위를 넓게 잡으면 본문 클릭이 제목을 오염시켜 제목이 깨지고 본문 첫 줄이 사라진다. 제목은 .se-title-text.
- **입력 순서는 본문 전체 먼저 → 제목은 맨 마지막** — 제목 직후 본문을 치면 레이스 컨디션으로 섞임이 재현된다. 제목 입력 후 실제 값을 읽어 초안과 비교하고, 불일치면 전체 선택·삭제 후 재입력. 본문 첫 줄도 저장 전에 앞 10여 자 포함 여부를 검사해 누락이면 맨 앞에 보정 삽입한다.
- 브라우저 뷰포트는 1600×1000 이상으로 — 1400 이하에서는 패널이 열릴 때 속성 툴바가 잘려 서식 버튼 클릭이 불안정해진다.
- 한글은 반드시 keyboard.insertText() — keyboard.type()은 IME 조합이 꼬여 오탈자 발생. 이모지는 별도 호출로 분리 삽입 (함께 넣으면 이모지 뒤 텍스트 유실).
- 인용구/구분선 버튼의 실제 클래스: se-insert-quotation-default-toolbar-button / se-insert-horizontal-line-default-toolbar-button. 추측 클래스명 금지.
- **소제목 서식은 볼드 토글로 하지 말 것** — 스마트에디터에선 선택 영역이 안 잡혀 실패한다. 문단 서식 드롭다운(se-text-format-toolbar-button → "소제목" 옵션)을 쓰면 캐럿만 놓여도 문단 전체에 적용된다. 기본 크기 30은 너무 커서 19(fs19 옵션)로 낮추되, 순서가 핵심: 서식 → 크기 → 텍스트 입력 (입력 후 바꾸면 이미 쓴 글자에 적용 안 됨). 입력 후 다음 문단은 "본문"으로 명시 복귀시키고, 드롭다운 라벨을 다시 읽어 적용 여부를 검증한다.
- text 블록이 연달아 오면 문단이 빈 줄 없이 붙어 렌더링된다 → 다음 블록도 text일 때만 끝에서 Enter를 한 번 더 누른다. 사진·소제목·인용구 앞은 에디터가 자체 여백을 준다.
- **태그 자동 입력**: 우상단 발행 버튼으로 패널을 열고 input#tag-input에 태그마다 입력+Enter로 칩 확정(입력 전 앞의 # 제거, 최대 30개) → Escape로 패널만 닫기 → 그 다음 임시저장. 패널 안에 진짜 발행 버튼이 있으므로 발행 차단 가드(절대 규칙 2)가 전제다. 태그 검증은 태그 영역 텍스트를 #로 쪼개 센다(칩 클래스는 해시가 바뀌므로 의존 금지).
- **지도(플레이스) 자동 첨부**: 지도 툴바 버튼 → 장소명 검색 → 결과가 여러 개면 place.name과 공백 제거 정확 일치 → 부분 포함 → 첫 결과 순으로 선택. 결과 항목의 "추가" 버튼은 hover 전에는 not visible이라 그냥 클릭하면 타임아웃 → 항목 hover 후 클릭(폴백은 DOM 직접 click). "추가" 전까지 확인 버튼은 disabled 상태. 장소 팝업은 Escape로 안 닫힌다 → 반드시 팝업 닫기 버튼 사용. 안 닫으면 dim 레이어가 남아 이후 모든 클릭이 "intercepts pointer events"로 실패한다.
- **동영상 자동 업로드**: 동영상 툴바 버튼 → 업로드 팝업의 "동영상 추가" 버튼이 파일 선택창을 띄운다. 제목 입력 필수(40자 제한). 팝업을 확실히 닫지 않으면 dim 잔류로 이후 클릭 전부 실패 — 닫기 실패 시 DOM에서 강제 제거 폴백까지 넣는다.
- 자동화 결과는 실행 로그 마지막에 "자동 처리 결과" 블록으로 항목별(태그/지도/동영상/소제목) 성공 여부를 출력하고, ❗수동 필요로 찍힌 항목만 사용자에게 안내한다.
- **--dry-run 플래그**: 저장 클릭만 생략하는 옵션을 스크립트에 넣는다 — 셀렉터 디버깅 중 "저장 글" 목록에 실패본이 쌓이지 않게. 셀렉터 수정 중엔 항상 이걸로 먼저 돌린다.
- 진입 시 "작성 중인 글" 팝업은 새로 쓰기(.se-popup-button-cancel)로 닫는다. 디버깅 재실행이 반복되면 네이버 "저장 글"에 실패본이 쌓이니 완료 보고 시 사용자에게 직접 정리 안내(자동 삭제 금지 — 파괴적 작업).
- 네이버 블로그 본문은 WebFetch 불가(도메인 차단)일 수 있다 — 재시도 말고 바로 사용자에게 본문 붙여넣기를 요청할 것.
- 셀렉터는 네이버가 수시로 바꾼다. 실패 시 probe 스크립트로 실제 DOM을 떠서 실측 후 수정하고, 3회 실패 시 수동 붙여넣기용 원고를 출력할 것.
