## 절대 규칙

1. **API 키 사용 금지** — 모든 AI 작업은 Claude Code 세션 안에서 (구독 토큰만 소모, `claude -p` 지원).
2. **발행 금지 — 임시저장까지만.** 발행은 항상 사람이. 태그 입력을 위해 발행 패널을 열어야 하므로, 에디터 로드 직후 캡처 단계 클릭 리스너로 진짜 발행 버튼(`button[data-testid="seOnePublishBtn"]`) 클릭을 원천 차단하는 가드(`installPublishGuard`)가 scripts/naver_draft.js에 들어 있다. **어떤 경우에도 이 가드를 제거하거나 우회하지 않는다.**
3. **사실 지어내기 금지** — data/profile.md와 사진에서 확인된 것만. 확인 안 된 정보는 사용자에게 묻는다.
   - 3-1. **협찬 처리(공정위 표시광고법 — 생략 불가)**: /write마다 협찬·체험단 여부를 반드시 확인하고(메모에 없으면 질문), 협찬이면 data/sponsored-disclosure.md의 대가 유형별 표기 문구를 글 상단 첫 블록에 기본 포함한다(업체 지정 문구가 있으면 그것이 우선, quote가 아닌 일반 text 블록으로). "내돈내산"·"광고 아님" 같은 거짓 부인 표현은 위법이므로 협찬 글에 쓰지 않는다.
4. 소재는 고객 사례가 아니어도 된다(자사 장비·일상 소재 가능). 단 서사를 지어내지 말고 정직하게 자기 사례임을 밝히고 쓴다.
5. **학습 데이터 자동 수집 금지** — 사용자가 제공한 글로만 data/trends.md, data/style-profile.md를 갱신한다.
6. **초안은 사용자 승인 후에만 임시저장.** 자동 모드여도 임시저장 전 검수 확인은 반드시 채팅으로 받는다 — 이 안전장치는 꺼지지 않는다.

## 글쓰기 공식 (실전 검증됨)

- **키워드**: 메인 1개(지역명 포함, 제목 앞쪽·첫 문단·마지막 문단 배치, 본문 5~7회, 띄어쓰기까지 검색어와 동일하게 1회 이상) + 서브 2~3개(소제목 배치).
- **페르소나 설계 필수**: 메인 키워드를 검색하는 1명을 구체적으로 정의(지역·나이·직책·상황·감정)하고 그 사람에게 말 걸듯 쓴다. 초안 검수 시 페르소나도 함께 보고한다.
- **첫 문단 Yes-set**: 첫 2~3문장에서 페르소나의 상황·감정을 적중시켜 "맞아, 내 얘기다"를 연속 유도 + 결론 예고.
- **둘째 문단 권위 한 줄**: data/authority-lines.md에서 골라 변형해 툭 던지듯. 자랑·업체명·연락처 금지. 정보성 글엔 "솔직함형"이 가장 강력.
- **후킹 패턴은 매번 다르게**: 손실 회피형 / 현장 몰입형 / 반전형 / 공감형.
- **홍보 냄새 제거**: 정보성 글 본문에 업체명 금지(CTA에서만 1회), 연락처는 글 전체 1회, 업체명 본문 3회 이내.
- **가독성(모바일 기준)**: 한 문장 = 한 줄, 한 블록 3~5줄, 리듬 파괴 장치(인용구/구분선/사진/소제목)를 300~400자마다, 핵심 문장은 인용구로 글당 2~4개. 텍스트만 500자 연속이면 실패작. 표는 "✔ 항목 — 내용" 체크리스트로 대체.
- **기본 세팅**: 1,800~2,500자(정보성 3,000자까지), 사진 10~15장(장당 텍스트 2~4문단), 제목 25~32자. 유사문서·저품질 회피(도입 패턴 매번 변경, 사진 재사용 금지, 외부링크 1개, 광고 어휘·제목 특수문자 금지). data/trends.md에 학습된 세팅이 있으면 그것이 우선.

## 초안 JSON 포맷 (drafts/*.json)

```json
{
  "title": "제목 (25~32자)",
  "blocks": [
    { "type": "text", "text": "한 문장 = 한 줄.\n다음 문장." },
    { "type": "subtitle", "text": "소제목 (서브 키워드 배치)" },
    { "type": "image", "path": "input/photos/xxx.jpg", "caption": "캡션 (절반 정도만, 키워드 1~2회)" },
    { "type": "quote", "text": "핵심 문장 (글당 2~4개)" },
    { "type": "divider" }
  ],
  "tags": ["태그1", "태그2"],
  "place": { "query": "검색어", "name": "정확한 상호명" },
  "video": { "path": "input/videos/xxx.mp4", "title": "40자 이내" }
}
```

- `tags`: 5~10개 권장, 최대 30개. 발행 패널에 자동 입력되어 임시저장에 보존된다.
- `place`: 지도가 글 맨 끝에 자동 삽입 — 지역 업종 글에서 필수. 검색 0건이면 로그에 수동 첨부 필요로 표시된다.
- `video`: 항상 첫 text 블록 직후 삽입(D.I.A. 가산 요소). title 필수·40자 제한(video.title > 글 제목 > 기본값 순). 업로드 수 분 소요.

## 사진·영상 처리

- 사진은 분석한 스토리 순서로 배치한다 (파일 순서 아님). 캡션에도 키워드 1~2회 자연 배치 — 전체 사진의 절반 정도만.
- **개인정보 모자이크 (scripts/mosaic.js, 필수)**: 사진에서 식별 가능한 타인 얼굴·차량 번호판·전화번호 등을 발견하면:
  1. 문제 영역 좌표(0~1 상대값, 상하좌우 15% 여유 포함)를 담은 spec JSON을 drafts/에 저장
  2. `node scripts/mosaic.js drafts/<spec>.json` 실행 — 처리본은 input/photos/_mosaic/에 생성, 원본은 절대 덮어쓰지 않는다
  3. 처리본을 Read로 열어 실제로 가려졌는지 확인, 덜 가려졌으면 좌표를 키워 재실행
  4. 초안에는 처리본 경로 사용
  - 좌표 기준은 반드시 EXIF 회전 보정 후(보이는 화면 기준). 검수 보고에 처리 내역(몇 장·몇 영역·사유)을 포함한다. 화자 본인 얼굴도 기본은 모자이크(공개를 명시한 경우만 예외).
- **동영상**: input/videos/에 영상이 있으면 초안의 video 필드에 넣는다.

## 자가 검증 원칙 (이 툴의 품질 엔진 — 가장 중요)

모든 단계에서 "했다"가 아니라 "됐는지 확인했다"로 끝내라:
1. **이중 검증**: 임시저장 후 (a) 스크린샷 + (b) 에디터 문서의 제목·본문 전체 텍스트 덤프(drafts/*-dump.txt)를 초안과 전문 대조한다. 스크린샷은 화면 상단만 보이므로 텍스트 덤프가 본검증이다. 불일치하면 성공 보고 금지 — 원인을 찾아 수정한다.
2. 셀렉터가 실패하면 추측으로 고치지 말고 `node scripts/probe_selectors.js`로 실제 DOM을 실측 후 수정한다. 3회 실패 시 수동 붙여넣기용 원고를 출력한다.
3. 문제를 해결하면 원인과 해결책을 이 파일 맨 아래 [트러블슈팅 기록]에 기록하고, 안정 버전 스크립트를 `.working.js`로 백업한다. 기억할 가치가 있는 건 전부 파일로 — 다음 세션은 대화를 기억하지 못한다.
4. 초안 검수 시 자가 질문: "모바일에서 인용구와 소제목만 훑어도 핵심이 전달되는가?"

## 실측 지식 (수십 시간 디버깅으로 확인 — 스크립트 수정 시 반드시 준수)

- 본문 셀렉터는 `.se-section-text p.se-text-paragraph` 로 한정. 제목도 내부적으로 같은 문단 구조(p.se-text-paragraph)라서, 범위를 넓게 잡으면 본문 클릭이 제목을 오염시킨다. 제목은 `.se-title-text`.
- **입력 순서는 본문 전체 먼저 → 제목은 맨 마지막** — 제목 직후 본문을 치면 레이스 컨디션으로 섞임이 재현된다. 제목 입력 후 실제 값을 읽어 초안과 비교, 불일치면 전체 선택·삭제 후 재입력. 본문 첫 줄도 저장 전에 앞 10여 자 포함 여부를 검사해 누락이면 맨 앞에 보정 삽입.
- 브라우저 뷰포트는 1600×1000 이상 — 1400 이하에서는 속성 툴바가 잘려 서식 버튼 클릭이 불안정.
- 한글은 반드시 `keyboard.insertText()` — `keyboard.type()`은 IME 조합이 꼬여 오탈자 발생. 이모지는 별도 호출로 분리 삽입 (함께 넣으면 이모지 뒤 텍스트 유실).
- 인용구/구분선 버튼의 실제 클래스: `se-insert-quotation-default-toolbar-button` / `se-insert-horizontal-line-default-toolbar-button`. 추측 클래스명 금지.
- **소제목 서식은 볼드 토글 금지** — 선택 영역이 안 잡혀 실패한다. 문단 서식 드롭다운(`se-text-format-toolbar-button` → "소제목" 옵션) 사용, 크기는 fs19로. 순서: 서식 → 크기 → 텍스트 입력. 입력 후 다음 문단은 "본문"으로 명시 복귀, 드롭다운 라벨을 다시 읽어 검증.
- text 블록이 연달아 오면 빈 줄 없이 붙는다 → 다음 블록도 text일 때만 끝에서 Enter 한 번 더. 사진·소제목·인용구 앞은 에디터가 자체 여백을 준다.
- **태그**: 우상단 발행 버튼으로 패널 열기 → `input#tag-input`에 태그마다 입력+Enter로 칩 확정(앞의 # 제거, 최대 30개) → Escape로 패널만 닫기 → 그 다음 임시저장. 태그 검증은 태그 영역 텍스트를 #로 쪼개 센다(칩 클래스는 해시가 바뀌므로 의존 금지).
- **지도**: 지도 툴바 버튼 → 장소명 검색 → place.name과 공백 제거 정확 일치 → 부분 포함 → 첫 결과 순 선택. "추가" 버튼은 hover 전에는 not visible → 항목 hover 후 클릭(폴백은 DOM 직접 click). "추가" 전까지 확인 버튼은 disabled. 장소 팝업은 Escape로 안 닫힌다 → 반드시 팝업 닫기 버튼. 안 닫으면 dim 레이어가 남아 이후 클릭 전부 "intercepts pointer events" 실패.
- **동영상**: 동영상 툴바 버튼 → 팝업의 "동영상 추가" 버튼이 파일 선택창을 띄움. 제목 입력 필수(40자). 팝업 닫기 실패 시 DOM에서 dim 강제 제거 폴백.
- 실행 로그 마지막의 "자동 처리 결과" 블록(태그/지도/동영상/소제목 항목별 성공 여부)을 확인하고, ❗수동 필요 항목만 사용자에게 안내한다.
- **--dry-run**: 저장 클릭만 생략. 셀렉터 수정 중엔 항상 이걸로 먼저 돌린다 ("저장 글"에 실패본이 쌓이지 않게).
- 진입 시 "작성 중인 글" 팝업은 새로 쓰기(`.se-popup-button-cancel`)로 닫는다. 디버깅 반복 시 네이버 "저장 글"에 실패본이 쌓이니 완료 보고 때 사용자에게 직접 정리 안내(자동 삭제 금지 — 파괴적 작업).
- 네이버 블로그 본문은 WebFetch 불가(도메인 차단)일 수 있다 — 재시도 말고 바로 사용자에게 본문 붙여넣기를 요청한다.

## 발행 체크리스트 (임시저장 후 안내)

태그·지도·동영상·소제목 서식은 스크립트가 자동 처리 — 실행 로그의 "자동 처리 결과"에서 실패 항목만 수동 안내한다. 그 외 수동 항목:
- 타겟 활동 시간대에 발행
- 발행 후 24시간 수정 금지
- 주 2~3회 주기 (하루 2건 이상 금지)
- 협찬 표기 육안 확인

## 사용자 안내 사항

브라우저 자동화는 네이버 약관상 회색지대(본인 계정, 하루 1~2건 권장). naver-profile/ 폴더는 로그인 세션이므로 외부 공유 금지. 이 툴은 "초안 공장"이지 "무인 발행기"가 아니다.
